## Part D – Understanding the concepts

### 1. Why is data understanding essential before training a machine learning model?

Data understanding helps identify what the dataset actually represents — its features, target variable, scale, distribution, and any quality issues such as missing values, duplicates, or outliers. Without this step, a model may be trained on flawed or misleading data, leading to poor performance, incorrect conclusions, or a model that fails to generalize to real-world data. It also guides key decisions such as which preprocessing steps, feature engineering methods, and algorithms are appropriate for the data.

### 2. What is the difference between univariate and bivariate analysis?

Univariate analysis examines a single variable at a time — for example, a histogram or boxplot of one feature — to understand its distribution, central tendency, and spread. Bivariate analysis examines the relationship between two variables at a time — for example, a scatter plot of MedInc vs MedHouseValue or a correlation coefficient — to understand how the two variables relate to or influence one another.

### 3. Why should duplicate records be removed?

Duplicate records give repeated data points extra, unearned weight during model training, which can bias the model's learned parameters toward those repeated patterns. They can also artificially inflate performance metrics if duplicates end up split across both the training and testing sets, giving a false sense of how well the model actually generalizes to new data.

### 4. Why can missing values reduce model performance?

Many machine learning algorithms cannot process missing values directly and will either throw an error or silently drop those rows, reducing the effective amount of training data available. If missing values are filled incorrectly (e.g., using an inappropriate imputation method), it can introduce bias or noise into the feature, distorting its true distribution and weakening the model's ability to learn accurate patterns.

### 5. What is data leakage? Give one example.

Data leakage occurs when information from outside the training dataset — particularly information from the test set, or information that would not be available at prediction time — is used to build or tune the model. This leads to unrealistically good performance during evaluation that does not hold up in real-world use.

**Example:** Scaling or imputing missing values (e.g., using the mean) on the entire dataset before splitting it into training and test sets. This causes statistics from the test set to "leak" into the training process, since the training set indirectly gains information about the test set's distribution.

### 6. Why must train-test splitting be performed before preprocessing?

Splitting the data first ensures that any preprocessing step that learns something from the data — such as computing the mean/median for imputation, or fitting a scaler — is learned only from the training set. The learned parameters (e.g., the training set's mean) are then applied to the test set, rather than being recalculated from it. This keeps the test set as a genuinely unseen sample, giving an honest estimate of how the model will perform on new, real-world data and avoiding data leakage.
